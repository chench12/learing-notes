# AlphaEvolve 方法重建与实验路线

更新日期：2026-11-12。本文是教学实现与研究实验的依据；当前智能体用法见 [agent_usage.md](agent_usage.md)。

## 1. 目标与复现边界

目标：依据 AlphaEvolve 原论文公开的方法，构建任务可替换、模型参数冻结、能够持续进行代码进化的系统，再通过对照与消融研究各组件的收益和代价。

首个研究任务是论文附录 B.12 的 26 圆装填；系统接口不绑定圆装填。当前使用中转服务返回的 `gpt-6.1-sol`，与论文的 Gemini 2.0 Flash + Pro 不同，因此称为替换模型的方法重建，不能宣称原条件严格复现。中转返回型号不构成模型身份的独立证明。

官方结果仓库明确不包含运行 AlphaEvolve 的系统源码。论文没有完整公开所有超参数、选择规则、提示词或训练以外的部署细节，因此以下所有自定规则均需记录，不能称为官方实现。

## 3. 当前实现审计

已经具备：数据协议、任务加载、固定评测器、模型接口、父代加反馈提示词、单次生成、独立实验清单/快照与环境指纹、进化区域及固定骨架校验、精确 SEARCH/REPLACE 补丁和显式完整重写模式。候选、生成尝试、重复评测分开保存。

P3 已部分实现：保存候选输出、分阶段日志、耗时、退出码、输出/日志哈希及限制信息；固定评测器移入独立进程并单独限时。Windows 使用 Job Object 限制总内存与活动进程数，结束时清理后代；候选加载前关联失败则停止。子进程使用环境白名单，不直接继承调用端 API Key。日志有界保存，工作目录和输出大小定期监测；后两者不是硬磁盘配额。

P3 已接入可选 Docker 后端：固定本地镜像 ID、无宿主挂载、禁用网络、只读根文件系统、非 root、内存/CPU/进程/tmpfs 限制，候选与评测器分容器运行，输入和有界输出通过管道传输，失败不回退本地。已提供离线协议测试和真实容器验收脚本。2026-11-12本机已完成WSL/Docker安装、手写种子双容器执行及8项真实集成验收，0跳过；配置、镜像与证据见 docker_on_this_pc.md。

P3 评测协议首版已实现：Evaluation 区分 objectives/constraints/features/stage；圆装填只有半径和一个优化目标，边界与重叠是约束残差，半径变异系数与边界接触比例是输出布局特征。特征定义留在任务包，不是论文的公开指定描述器，现已用于 P5 档案分格。

重复复核组保存计划、各次原始评测、合法率和合法样本的均值/中位数/样本标准差。采用本项目自定的 all-valid-median-v1 汇总规则；confirmation与search隔离。控制器已可对超过调用前全局最佳的子代自动同预算复核，搜索与复核计入统一评测预算；统计独立性控制仍未实现。

P4 首版已实现：SQLite 保存当前候选/生成/评测/复核组、冻结的选择计划、修订事件及文件导出清单，内容文件用哈希寻址保留；事务提交后可补齐中断导出。OS 单实验锁覆盖整个操作。生成前预分配子代/评测编号，响应提交后可离线继续，重复恢复不新增候选/已完成评测；未知外部请求结果标为 uncertain，不重发。遗留评测/复核组可协调状态，缺失的执行须显式新建评测。

P5 首版已实现：每岛维护布局特征格、从非空格均匀抽父代、同时环形迁移，选择前快照固定到生成计划；按事实事件重建视图和迁移历史，保留贪心对照。具体边界、容量、同分和复测规则为本项目设计，见 [archive_selection.md](archive_selection.md)。

P6—P10 首版已落地：按预算采样完整历史代码/材料/日志和指令模板；串行自动循环及跨启动预算；结构/标准执行/可选自动复核；加权模型路由；独立附加指令档案与固定窗口父子增量信用。统一call账本覆盖程序与元指令请求，响应提交后可恢复，未知结果不重发。具体自定规则及限制见 agent_usage.md。

P11已新增本机单实验有界异步流水线：单写入协调器、在途任务上限、模型/评测信号量、子代评测预留、乱序提交与取消排空。第二装箱任务和独立实验批处理也已完成首版。具体规则见 async_pipeline.md。正式付费研究结果、跨机租约/恢复、LLM评审插件和大型历史增量索引仍未实现；不等于论文原部署条件。旧实验自动迁移、孤立容器自动清理也未实现。

当前结构化字段不代表已实现多目标选择。`max_violation` 是约束诊断量；`objectives.sum_radii`、`metrics.sum_radii` 与 `score` 是同一质量指标。

当前 `best()` 是独立全局最佳查询，父代来自配置的选择器。保留单次脚本；连续运行入口为 Examples.run_search，离线夹具可本地运行，真实自动生成要求Docker，本机已完成实际隔离验收，尚未开展正式模型实验。

## 4. 最终组件边界

任务包：任务描述、完整种子程序、固定评测器、特征描述器、可选参考材料、评测配置。任何任务专有几何逻辑留在任务包。

通用系统：任务与实验配置、骨架/进化块管理、提示词构造、模型适配/路由、生成解析/补丁、候选执行、评测流水线、记录存储、档案/选择、控制器、分析工具。

记录存储负责保留事实；活跃档案负责繁殖选择。落选或失败记录不删除。档案策略升级后，可以依据记录重建，而不重新调用模型。

核心流程：加载配置 → 选择岛屿/父代/参考程序/提示词模板/模型 → 保存生成计划 → 请求模型 → 解析补丁或重写 → 校验骨架 → 执行与级联评测 → 持久化结果 → 更新档案与预算 → 下一轮。

## 5. 完整实施顺序与验收条件

### P0：冻结当前基线与实验身份

新增统一实验配置和清单，保留当前单次生成脚本作为基线。记录任务 ID、种子代码、评测器、任务描述、特征/分格规则、依赖版本、Python 路径、模型服务/型号、提示词版本、运行与生成预算。文件内容计算哈希；密钥仅存在调用端环境，不写入清单。

区分 experiment_id、candidate_id、generation_attempt_id、evaluation_attempt_id。一个候选可以有多次评测，不能覆盖旧成绩。父代复测归属于父代的独立评测记录。

旧 `runs` 标为探索性旧格式；缺失评测身份的记录不能自动混入新实验。允许明确导入旧代码并在新配置下重新评测，保留来源关系。

验收：相同代码不同预算不能悄悄混排；候选、生成与评测身份可追溯；不调用模型。

### P1：骨架与可进化区域

新增 `Evolve/blocks.py`，解析多组 `# EVOLVE-BLOCK-START` / `# EVOLVE-BLOCK-END`。拒绝缺失、错配和嵌套标记；保留固定片段。完整重写模式也必须保留固定片段和块顺序。

任务仍提供完整可运行的种子，不使用省略号占位程序。圆装填允许共同修改初始化和优化函数，避免过窄接口人为限制搜索；接口和结果包装留在固定区域。若要进化导入语句，须将相应导入块明确标记。

验收：跨多个进化块合法修改能通过；越界修改、删除标记、改变固定入口被拒绝；原程序照常运行。

### P2：补丁协议与失败分类

新增 `Evolve/patches.py`，支持连续 SEARCH/REPLACE 块。约定在当前工作副本上按顺序精确匹配；搜索片段必须唯一，空搜索和歧义匹配拒绝。不做静默模糊匹配。全部补丁应用并校验成功后才构造子代，失败不产生半修改程序。

输出解析区分解释文字与补丁；原始响应始终保存。完整重写作为独立配置模式，不在补丁失败后无记录地切换。

生成状态独立于评测状态，例如 api_error、truncated、parse_error、patch_error、skeleton_error、syntax_error。失败尝试也消耗调用与 token 预算；修复调用必须作为有父子关系的新尝试计数。

验收：多处修改、重复匹配、缺失匹配、格式错误、越界修改、截断均有确定结果；优先离线验证。

### P3：执行产物、受控执行和评测协议

修改 runner/worker，保存 solution.json、执行日志、耗时、退出码、异常及环境身份。评测器与描述器在固定配置下消费候选输出。通用框架不假设输出是圆。

将评测结果拆为状态、优化指标、约束诊断、特征描述、反馈和阶段标识。重复评测独立保存；聚合方法预先设定，并同时报告合法率、均值/中位数和波动。最佳布局及其验证记录独立保存。

在持续自动运行前引入实际系统级执行隔离：宿主调用模型，隔离执行节点运行候选；候选端无服务密钥、无网络、不能修改评测器/宿主档案，限制 CPU、内存、磁盘、日志和进程树。Windows 使用何种隔离后端在此阶段验证，可采用可用的容器或独立执行虚拟机；无可用后端时维持人工审查和单次运行，不宣称已经安全隔离。

验收：成功、非法解、语法/运行异常、超时、缺输出、大输出、子进程清理和产物保存均可检查；候选无法读到宿主测试用凭据或写入固定评测区域。

### P4：持久记录与恢复基础

新增 `Evolve/storage.py`，使用 SQLite 维护候选、生成尝试、评测尝试、选择计划与事件；大文件保存在实验目录，数据库保存路径和哈希。事务提交，最终文件用原子替换，记录计划、发出、响应收到、子代构造、评测完成等状态。

每次外部调用前保存完整生成计划，包括候选池快照、父代、参考程序、模板、模型、随机种子与参数。调用超时但未知服务端是否完成时，标记 uncertain；恢复不盲目重发同一调用。已经收到的响应能离线继续处理。

验收：中断后完成记录不丢失、不重复入库；成功响应不会因恢复重复计费；不完整目录有可解释状态。

### P5：岛屿与 MAP-Elites 思想的混合档案

新增 `Evolve/archive.py`、`Evolve/selection.py`，读取持久记录，维护活跃成员。明确这是我们依据论文思想设计的重建策略。

首版约定：每座岛维护一个特征网格；父代从岛内占用格中选择，同格按预定义质量规则保留代表。多个评价目标可用多个档案视图，而非随意把数值相加。全局最高分单独查询，不自动成为每轮父代。

待配置内容：岛数量、选岛规则、特征定义和边界、格子容量、同分规则、种子分配、父代采样、参考程序来源、迁移周期/数量、是否重启及重启条件。具体数值通过预实验校准，正式比较前冻结。迁移导入仍经过目标岛的同格替换规则，迁移不伪造新候选。

圆装填可先考察半径变异系数与接近边界的圆比例；边界接触阈值独立定义，不与合法性容差混用。这些特征只反映输出布局，不会自动识别 Adam/L-BFGS。可以比较代码复杂度等替代特征，但须作为不同策略实验。

代码精确/AST 去重可降低重复采样；程序输出相同不意味着程序等价。重复源代码的多次评测属于同一候选统计，不以最高一次成绩替换全部记录。

验收：填新格、同格竞争、低全局分但不同格的候选保留、岛间独立性、迁移、种子复现及基于事件重建一致。

### P6：丰富上下文与提示词采样

扩展 `prompts.py`：固定问题说明/公式/材料、接口与进化范围、依赖和预算、历史参考程序及其结果、当前父代及结果、补丁规则和例子、本次改进指令。

父代是补丁应用对象；参考程序只作为灵感，记录 inspiration_ids，不把它们误记为直接父代。固定保留任务/父代/协议，历史参考按上下文预算选择或裁剪，不截断为不可用代码。记录检索、裁剪及随机模板实例化结果。

按需要附加数值诊断、布局统计、日志摘要。原文支持渲染结果和文献等上下文，不要求首版支持图片/PDF输入；文本实现先完整跑通。参考材料若包含当前最优布局，必须说明实验是从该材料起步，不能再宣称独立重新发现。

验收：一个父代、多份参考、多个指标与明确补丁规则构成可检查提示词；模板选择可复现且不访问未来结果。

### P7：串行自动多轮控制器

新增 `Evolve/controller.py`，组织完整循环；支持候选/调用数、token、评测时间、总墙钟时间和可核实的费用预算。发起请求前检查剩余预算并预留输出预算；无法精确获知服务端计费时不能保证精确金额上限。计入失败、重试、修复和元提示词调用。

先完成串行正确性，直接使用 P5 的混合档案；贪心策略作为显式对照开关，不作为唯一主流程。所有模型调用必须使用指定父代，不在循环内误读回最初种子。

验收：用离线模型响应完成多轮，观察父子关系和档案变化；可停止、恢复、达到预算停止；再由用户启动少量真实调用。

### P8：级联评测与多分数

新增 `Evolve/evaluation.py`：结构/骨架/语法初筛 → 候选执行与约束检查 → 标准预算评测 → 对有希望的候选独立确认。按任务定义是否需要更低预算初筛或更多种子，不默认对所有任务适用。

特别注意：当前生成的圆装填代码内部硬编码 2.65/2.82 秒循环。直接用 0.5 秒初筛会把这些程序全部判为超时，而不是可靠筛选质量。若要进行计算预算级联，先明确算法预算接口并固定骨架，例如任务约定的 solve(budget, seed)；这是我们的接口扩展，需要同步更新初始程序、提示词和任务版本。也可保持 solve() 并只做不改变求解预算的前置检查。

不同阶段成绩分别保存，初筛低预算分不能与完整预算分混排。高预算确认属于单独结果；不能拿更长计算时间的成绩冒充标准三秒成绩。多个重复评测最初串行，避免同机争用影响按时间停止的算法。

验收：各阶段消耗和淘汰原因可见；确认阶段与搜索反馈隔离策略明确；关闭级联的对照使用可比较预算。

### P9：模型组合

新增模型路由，配置不同模型、服务、权重/触发条件和输出限制。原文 Flash/Pro 的精确配比未公开，不凭空称某一比例为原配方。当前中转只核实接口连通，记录请求名、响应名、服务、版本信息与真实用量。

先固定模型组合策略，再比较单模型与组合。价格配置带日期与来源；中转缺少实际账单时报告 token 和平台计费记录，不能用官方直连价格冒充实际成本。

验收：离线验证路由与预算；真实调用由用户控制；不同模型贡献和失败率分别统计。

### P10：元提示词进化与可选 LLM 反馈

新增 `Evolve/meta_prompts.py`。提示词作为独立候选对象，拥有自己的档案和谱系；元提示词生成步骤提出新指令/上下文，不能修改固定评测规则、越过代码区域或删除实验约束。

通过预先规定的若干后续生成，估计提示词的改进收益/成本，记录它使用的父代质量、模型和任务条件。一个子代的最终分数不能直接被当作提示词质量，否则优秀父代会造成混淆。信用分配方案为自定设计，先用固定子预算比较，保留禁用开关。

LLM 对简洁性等反馈作为可选插件；不替代几何合法性和数值验证，调用成本计入预算。随机格式、元提示词、LLM反馈分别配置，便于消融。

验收：程序档案与提示词档案可区分；提示词影响路径可追溯；关闭功能后生成链仍完整运行。

### P11：异步流水线与任务替换验证

用 asyncio 实现 controller、LLM samplers、evaluation workers 的有界队列；限制在途调用和评测数，原子处理档案更新。计划时固定父代版本与上下文，不因后续数据库变化改变已经发出的请求。

先并行生成、限制本地 CPU 评测并发，依据实测再增加。多进程评测竞争 CPU 会影响当前时间预算求解器；记录并发与机器配置，不能把并发引起的质量变化当算法收益。异步事件顺序需保存；固定随机种子不保证远程模型和异步运行完全复现，但保存响应后应能重放档案更新。

接入第二个不同任务，只新增任务包/配置，检查通用模块无圆装填专有逻辑。单文件多函数是首个完整范围；任意语言、多文件进化是后续扩展，非当前已完成能力。

验收：队列、取消、预算预留和恢复可运行；重放同一完成事件序列得到相同档案；第二任务无需修改核心搜索逻辑。

### P12：正式实验与论文分析

预实验只校准延迟、失败率、档案占用和费用，不用于选择最终测试结果。锁定初始程序、任务/环境、模型配置、评测预算、选择策略和停止条件后再正式重复。

对应论文第4节的设计：无进化（始终初始程序）、无额外显式任务上下文（仍保留必要目标/接口）、无元提示词进化、只允许单函数修改、仅较小模型。圆装填上的结果属于迁移原文实验设计，不能宣称重现原论文张量分解/kissing number 消融的结论。

额外实验：贪心/仅岛屿/仅网格/混合档案；父代单独上下文/历史参考；补丁/完整重写；级联/不级联；传统数值优化增加计算与 LLM 进化的比较。这些是我们新增的问题，不是原文已有消融。

先做一个主对照和少量关键消融，避免全因子组合耗尽预算。每种主要设置争取5个独立搜索种子，预算有限先3个并如实报告；原论文消融展示3次独立运行。生成种子不保证模型输出确定，完整保存输出。

同时报告最佳合法布局、候选算法重复评测的质量和成功率、最佳分数随调用/token/费用变化、失败原因、档案覆盖和有效多样性、生成/评测耗时。不同大小模型和上下文长度下，调用数相同不等于成本相同；分别做等调用预算与等token/费用分析。

最终优秀布局独立复核，容差、精度和坐标必须提供；浮点合法不等于全局最优性证明。搜索预算与最终独立确认成本分别报告。公开最优布局可以校验评测器，不能默认注入所有搜索作为隐含初始解。
