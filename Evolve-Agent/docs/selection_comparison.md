# 均匀、温度采样与 PUCT：三策略对照

三种父代选择已接入当前智能体，默认仍是uniform_cell。框架清单现为schema 9，需新建实验；串行控制器、历史上下文、统一预算和模型路由用法见 [agent_usage.md](agent_usage.md)。串行/异步模式及并发参数也必须一致，不能混排。旧实验及selection_plan_v1保留为历史，不修改清单绕过检查。

## 比较的是哪个问题

在冻结 LLM、相同岛屿特征档案、迁移、提示词和执行预算下，父代应该按以下哪种规则选择？

| 配置 archive.parent_sampling | 选择依据 | 探索与利用方式 | 主要弱点 |
|---|---|---|---|
| uniform_cell | 岛内非空格均匀采样 | 格间均匀探索，格内择优利用 | 很差的新格与优秀格有同等繁殖概率 |
| softmax_cell | 当前代表质量的带温度 softmax | 高温分散、低温偏向高分；周期恢复温度 | 不判断某父代产生改进的能力，受奖励尺度影响 |
| puct_cell | 最好直接子代质量 + 排名先验 × 访问奖励 | 利用有产出的父代，给少访问分支更多探索奖励 | 最大值容易被偶然成功误导，统计和边界规则更复杂 |

三者都轮询岛屿，都只在当前岛的活跃格代表中选择。共用每格容量1、特征边界、最新搜索成绩规则和每完成4代的同时环形迁移。均匀策略也是有效的质量—多样性基线，不把它描述成“完全没有利用”。

实验对象是**生成程序作为父代**，不是直接把圆布局当成状态。换成第二任务时，选择器不需要知道圆的坐标。

## 对论文采用了什么、改了什么

[FunSearch 官方程序数据库](https://github.com/google-deepmind/funsearch/blob/main/implementation/programs_database.py) 按测试分数向量聚簇，对簇质量做带温度 softmax；温度随岛内注册程序数周期下降，同簇偏向短程序，并定期重置较差岛屿。

本轮只借用其温度采样思想，应用到现有几何特征格。没有引入分数签名聚类、短程序偏好或重置；温度周期改为该岛已发起的生成次数，避免与另两组改变多项机制。因此 `softmax_cell` 是 FunSearch 启发的选择器，不是完整 FunSearch 复现。

[TTT-Discover 附录 A.2](https://arxiv.org/html/2601.16175v1) 给出：

\[
U(s)=Q(s)+c\,(R_{\max}-R_{\min})P(s)\frac{\sqrt{1+T}}{1+n(s)}.
\]

其中先验按奖励降序的线性排名计算；Q 使用最好直接子代奖励，访问数回传祖先。本轮借用这部分搜索规则，LLM 参数冻结，没有实现原论文的强化学习更新，也没有照搬其每父代保留 top-2 子代、全局 top-1000 状态的档案。PUCT 作用于岛内活跃格，不是论文中的全局状态档案。

本项目额外明确的规则：

- `T`、`n`、父代直接扩展数分别按岛维护。迁移后仍是同一候选 ID，但不从来源岛复制这些统计；在目标岛首次投入可获得探索机会。选中父代的访问数会回传其祖先，在本次选岛中计数。
- 首次保存 `requesting`（或恢复记录中已有更后阶段）就计一次投入。同一生成的状态更新和重复恢复不重复计数。API结果未知、API拒绝、补丁/语法失败仍消耗一次投入；只保存 `planned` 尚未发起的请求不计。
- 完成的生成链用其原计划实际对应的 `search + standard` 子代评测给直接父代记奖励。不是所有复测都产生新的繁殖奖励。confirmation 不参与；只有合法子代有质量信用。未产生合法子代时 Q 回退到父代当前分数，不把失败当0分。
- Q 是历史最好直接子代结果，后来的复测不改写原生成的信用；这与档案代表使用“最近一次已完成搜索成绩”是两种不同语义。应警惕随机求解器的偶然高分，因此最终仍需独立复核。
- 排名先验为 `(N-rank)/(N*(N+1)/2)`；同分按候选 ID 排序。最大 PUCT 分同分时按冻结随机种子打破平局，不对全部 PUCT 分再做 softmax。
- 奖励范围由**当前岛活跃代表**计算。全部同分时原公式范围为0，本项目明确用1个奖励单位恢复探索项。日志记录该回退，不把它称为论文原始规则。正常范围使用公共单位缩放整个公式以防数值溢出，不改变最大分选择结果。
- 父代复测失败仍按原流程停止，本轮不隐式重新选择父代。相同父代继续失败时应先检查恢复/复测记录，不靠自动换父代隐藏问题。

默认 `temperature_initial=0.25`，`temperature_period=20`，`puct_c=1.0`。温度为 `0.25*(1-(T % 20)/20)`，周期内最小为0.0125，随后恢复0.25。它们是预实验起点，没有宣称是论文最优参数。正式实验前校准并冻结，不事后为每组挑最好的参数。

## 先看离线机制对照

```powershell
python -X utf8 -m Examples.compare_selection --demo
```

输出到新建的 comparisons 目录，不需要密钥。示例假设三个父代当前分数为 A=2.60、B=2.50、C=2.30；这些是假设数值，不是运行得到的圆装填成绩。

| 固定档案情境 | 均匀抽格 | 温度采样 | PUCT |
|---|---|---|---|
| 都未扩展 | A/B/C各33.3% | A约50.7%，B约34.0%，C约15.3% | 选A |
| A扩展60次；B扩展5次且产生过2.64分子代 | 各33.3% | A约55.9%，B约32.8%，C约11.3% | 选B |
| A/B各扩展50次，C未扩展 | 各33.3% | A约50.7%，B约34.0%，C约15.3% | 选C |

`mechanism_demo.json` 保存每个候选的概率、Q、访问次数、先验、探索项和选择分数。默认对每份固定快照查询1000次以检查采样。查询之间不更新反馈，所以这不是1000轮搜索，PUCT保持选择同一个最大分父代是预期行为。

这份演示回答“策略的行为有什么不同”，不回答“谁能发现更好的程序”。三策略真实生成、保存响应后恢复以及幂等计数还由离线集成测试覆盖。

## 准备同预算的真实实验

```powershell
python -X utf8 -m Examples.compare_selection --prepare --seeds 42 43 44 --generations 100
```

仅生成9份配置（三策略 × 三种子），每份最多100条生成计划，合计最多900条计划；不创建实验、不调用模型、不自动执行900次。预算允许时正式比较可增加独立种子。相同搜索 seed 不保证远程 LLM 输出相同，也不保证这是完全相同的随机轨迹。

selection_plan_v1是此前框架的历史计划。请用上面的prepare命令为当前框架生成新目录。模型服务、模型名、上下文、预算和执行后端沿用当前配置；修改共同条件时重新准备整组，不只改其中一种策略。

按计划中的配置新建某一组：

```powershell
python -X utf8 -m Examples.generate_candidate --config comparisons/新计划目录/uniform_cell_seed42.json
python -X utf8 -m Examples.generate_candidate --config comparisons/新计划目录/softmax_cell_seed42.json
python -X utf8 -m Examples.generate_candidate --config comparisons/新计划目录/puct_cell_seed42.json
```

以上每条会发起一次真实模型调用并创建独立实验。把每组实际实验目录记下来；下一代对同一目录使用 `--experiment`，不要重复用 `--config` 从头创建实验。另两个 seed 同理。

默认仍是local-reviewed，真实Docker隔离尚未验收；没有替你启动真实批量调用。串行控制器已实现；按sandbox_setup.md验收后，用匹配Docker配置运行run_search。当前本地配置先用于人工审查试跑。

100条计划是等上限，不保证100次请求。各组实际程序/元指令调用数、未知结果、token和确认评测成本必须同时报告。统一预算已经实现，但参考费用不等于实际账单，等调用也不等于等token/费用。

## 比较已运行的结果

对完全相同 seed 集合的三组实验，传入所有实际目录：

```powershell
python -X utf8 -m Examples.compare_selection --experiments experiments/exp_均匀42 experiments/exp_温度42 experiments/exp_PUCT42
```

三种子时传入9个目录。命令只读取数据，写入新的 comparisons 输出目录，不调用模型、不执行候选、不改变实验档案。要求任务、模型、框架快照、环境、预算、迁移及所有其他配置一致；只允许采样方法和搜索 seed 不同。缺策略、缺种子或同一策略/seed有多份实验会拒绝，避免无意中挑选最好结果。

输出：

- `results.json`：每次运行与每策略的描述性汇总；未完成预算的结果标为进度快照。
- `runs.csv`：最新搜索成绩下的全局最佳、历史最高观测、格子覆盖率、不同活跃候选数、父代选择熵、子代合法率、已发起请求数、已知token、用量是否完整、评测耗时和生成失败分类。
- `trace.csv`：逐搜索评测的分数、当时的全局最佳、请求计数和已知累计token，可用于绘制得分—成本曲线。曲线允许因复测失效而下降；不会把历史幸运峰值当成当前可靠最佳。

未知服务端结果不记为0成本：已知token和 `token_accounting_complete=false` 同时报告。响应声明的模型名也单独列出；中转是否真正提供该型号仍需服务方记录支持。确认评测与搜索费用分开保存，报告中的时间当前是搜索评测时间。

优先比较最终独立复核质量、发现改进所需调用/token、失败率和跨种子波动。覆盖率/选择熵是机制诊断，不能单凭覆盖更多就判胜。当前报告不自动执行独立复核或显著性检验；未完成预算、调用数不相等时会明确提示，不能据此宣称某策略更优。

## 代码阅读

`Evolve/selection.py` 的 `selection_weights` 实现三种规则，`rebuild_search_statistics` 从事务事件重建反馈。`session.select_parent` 传入同一档案与统计，`generation.plan.selection.diagnostics` 固定当时全部候选的选择依据；响应恢复仍复用原父代/岛屿，不重新选择。

`Evolve/comparison.py` 生成匹配配置、检查可比性并汇总成本/质量。`tests/test_selection.py` 检查公式及信用分配；`tests/test_comparison.py` 检查三种策略在真实持久化/候选执行/中断恢复中的行为。
