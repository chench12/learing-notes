## 实现了什么

原先一次生成持有锁直到模型请求与评测结束。现在分为冻结计划、发出请求、提交响应、准备候选、执行评测与提交结果几个阶段。事件循环中的协调器唯一写库；线程只执行外部请求或候选程序，避免线程争夺数据库和实验锁。

生成任务、模型调用和评测分别限流。默认最多4个在途任务、2个程序请求、1个评测；允许配置两个评测工作槽，但正式实验需要记录CPU争用条件。父代准备仍顺序进行，以保证选择序号和计划身份一致。

请求前保存调用预留，同时保留子代完整评测额度。排队期间后续父代复测不能消耗这笔额度。STOP或协程取消会关闭新请求准入，已开始的外部操作排空落盘后才释放锁。未发送的计划标记not_sent，不记作父代访问或API调用；结果未知的请求仍不自动重发。

元指令与重复确认放在排空屏障处，继续串行执行；它们尚不是独立异步节点。跨机工作节点、租约与大规模存储索引也未实现。原有三种父代选择都走相同的异步流程，配置与并发条件不同的实验不能混排。

## 你现在可以怎样运行

在项目根目录创建自己的新实验：

```powershell
python -X utf8 -m Examples.run_async_search --config configs/circle_packing.async.offline.json --offline-demo
```

上面保存的演示由 D:\Anaconda\python.exe 创建，环境身份已冻结。若要用CLI重新打开它，应使用同一解释器；在自己的pytorch环境中学习和运行时，用上述命令创建属于该环境的新实验即可。schema 8及更早的历史目录保持原样，不修改manifest绕过检查。

完整机制、预算语义、停止/恢复和真实运行条件见 [async_pipeline.md](async_pipeline.md)。本机仍缺少Docker/Podman，真实隔离验收及正式付费模型对照尚未运行。本次完成的是可离线验证的本机异步首版，不代表论文结果或生产部署已复现。
