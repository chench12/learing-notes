# P5：岛屿、特征网格与父代选择

实现对应 [AlphaEvolve §2.5](https://arxiv.org/html/2506.13131v1)：程序数据库受 MAP-Elites 和岛屿模型共同启发。论文没有公开网格边界、迁移频率、采样概率等具体规则。下面是本项目的明确重建方案，不是 DeepMind 原始代码或原始超参数。

## 如何运行和观察

先在项目根目录运行离线演示：

```powershell
python -X utf8 -m Examples.check_archive
```

这会新建独立实验，用四份人工编写的补丁走完整的生成、执行、评测和入档流程。没有模型客户端，不需要 API Key，真实 API 调用为零。布局分别是缩小半径的网格、25 圆网格加一个孔隙圆、略有大小差异的网格，以及另一份缩小半径网格。它们用于验收框架，不是 LLM 发现的新算法。

预期可以观察到：

- 岛0同时保留种子约 2.166667 和小半径布局 2.0：后者分数低，但在另一个特征格。
- 岛1的手写布局约 2.541421，成为全局最佳；一次迁移后出现在岛2。
- 同一轮迁移不会把该布局从岛1连续传到岛2、岛3。岛屿独立发展与交换的边界可以检查。
- 对冻结档案的抽样查询能抽到低分布局。查询不执行额外代数，也不改变档案。
- 重新打开实验、重建档案、再次同步导出后，档案内容和数据库记录数保持一致。

查看上一步输出的实验目录：

```powershell
python -X utf8 -m Examples.inspect_archive --experiment dev_runs/exp_实际编号
python -X utf8 -m Examples.inspect_archive --experiment dev_runs/exp_实际编号 --json
```

第一条显示全局最佳、各岛的格子/候选/分数和迁移轮数。第二条打印完整重建视图。这两个命令不执行候选、不抽取下一代、不提交新的迁移。首次打开仍会按存储协议补齐已提交的待导出文件。

`Examples.generate_candidate` 仍是手动一次一代；串行控制器见agent_usage.md，单实验异步入口见async_pipeline.md。真实模型调用由你启动。当前schema 9，旧实验保留原样，新框架需要创建新实验。

后续已增加 `uniform_cell`、FunSearch启发的 `softmax_cell` 和 TTT-Discover启发的 `puct_cell` 三种父代采样。默认仍为均匀抽格；本页描述共用档案及默认行为。公式、适配差异、反馈统计、对照配置及结果分析见 [selection_comparison.md](selection_comparison.md)。

## 格子如何定义

特征计算放在任务评测器，通用档案只读 `Evaluation.features`。默认配置：

| 项目 | 本项目当前规则 |
|---|---|
| 岛数量 | 4 |
| 横轴 radius_cv | 半径总体标准差 / 平均半径；边界 0、0.05、0.15、0.35、0.75、1.5、5.000001 |
| 纵轴 boundary_fraction | 与至少一条边距离不超过 1e-6 的圆占比；边界 0、0.25、0.5、0.75、1 |
| 格子容量 | 每岛每格 1 个活跃代表，共 24 格/岛 |
| 区间规则 | 左闭右开；最后一格包含最右端；边界值进入右侧格子 |
| 缺失、非有限或越界特征 | 不入特征档案，记录原因；不截断数值；原始评测仍保留 |
| 同格比较 | 半径和越大越好；分数完全相同则候选 ID 字典序较小者胜 |

种子的特征为 `(0, 0.5)`，格子编号为 `[0, 2]`。半径缩为 1/13 后，边界接触比例变为 0，进入 `[0, 0]`，因此可以与种子共存。特征不参与分数相加，也不识别“Adam/L-BFGS”等源代码类别。radius_cv 上界覆盖 26 个正半径的理论范围（CV < sqrt(25)=5），不预设所有布局近似等半径。

所有根候选（没有父代）分配到全部岛屿；生成的子代归属生成计划里固定的岛屿。共用种子 ID，不复制出四个虚假的候选。各岛独立竞争格子；只有迁移能把子代引入其他岛。

## 如何选父代

已提交的生成计划数从 0 开始作为 `selection_index`。默认先轮询岛屿：`island_id = selection_index % 4`，再在该岛所有非空格中等概率选择一个代表。抽样随机数由策略版本、`search.seed` 和选择序号的 SHA-256 派生。档案按格子编号排序，不依赖字典或 UUID 的遍历顺序。

首次某岛无合法活跃格时，明确回退到任务种子，并保存 `fallback=seed`。不会偷偷回退到其他岛的全局最佳。父代本次复测不合法则停止该次流程，不隐式换父代。读取/检查不推进序号；计划提交后才占用生成次数，因此有计划的 API/解析失败也会推进选岛，而父代复测失败尚未建立生成计划，不推进。

`session.best()` 单独查询所有候选最近一次已完成搜索评测的最高合法分，包括不在活跃格中的候选；它不参与默认的父代抽样。模型参数仍然冻结，这里改变的是搜索状态与上下文。

配置 `archive.strategy = "greedy"` 可创建贪心对照实验：父代始终来自 `best()`，关闭迁移；其他模型、评测预算、种子和补丁协议保持相同。配置必须在新建实验前修改，不编辑历史 manifest。`archive.islands=1` 可做仅网格对照，迁移为空操作；这两个配置不是正式优劣结论。

## 复测、淘汰和迁移

每个候选使用**最近一次已完成的 search + standard 评测**，最近按 SQLite 事务提交顺序判定，不用时间戳或随机 UUID 排序。运行中的评测不抢占旧结果；最近完成的非法/超时/错误结果撤销该候选的活跃代表资格。特征变化则换格，分数降低则重新竞争，不保留历史最好一次。confirmation 复核完全排除。

候选在本岛的归属资格保留。每次重建时，同岛所有有资格候选按最新结果竞争各格，因此之前落选者可能在原代表复测变差后重新成为代表。落选、失败、旧成绩和源码都不会删除；这个“重新竞争全部有资格候选”的规则是我们的设计，不能等同于经典的只保存精英且丢弃其他候选的 MAP-Elites。

默认每完成 4 条生成链触发一次迁移，包括已经实际评测、但子代结果非法的链；API/语法等未评测完成的失败不触发。触发计数与选岛计数有意区分，并在迁移记录中保存。

迁移先冻结全部供体/目标的活跃格。每岛按质量取最高的 1 个代表，同时沿 `0→1→2→3→0` 发送。目标空格接受；目标同格仅接受质量更好的代表。同 ID 已在该格时不重复接纳。不创建新候选、不执行新评测、不在同轮连续传播。迁移保留来源岛、目标岛、原候选/评测 ID、特征格、分数、目标原代表和接受结果。

迁入成功意味着增加目标岛的归属资格；后续该候选复测变差/失败会影响它所在的所有岛。各岛共享同一程序的最新搜索结果，不各自挑选它最幸运的评测。目前不重启岛屿，没有隐藏的停滞重置策略。

## 持久化和恢复如何保证一致

数据流为：选择前读取事实并重建档案 → 选择父代 → 复测父代 → 冻结生成计划 → 请求一次模型 → 保存响应 → 构造并评测子代 → 提交生成完成状态 → 重建档案/迁移 → 导出。

生成计划的 `selection` 保存选择序号、岛屿、抽到的格子、历史评测 ID、随机种子派生值和完整选择前档案快照；`parent_evaluation_attempt_id` 保存随后本次复测的编号。两者用途不同。恢复已保存响应直接使用原计划，不重新抽样父代或岛屿，也不会重新请求模型。

`records.sqlite3` 的候选/生成/评测事件是事实来源，事件按 sequence 重放。档案遇到某代首次完成事件且达到迁移周期时，使用**当时已提交**的成绩计算迁移；后来的复测不能改变历史迁移决定。重复的完成状态不触发第二次迁移。迁移是由事实确定的派生事件，随档案快照一起保存，不是额外的模型调用或候选。

`archives/current.json` 是物化视图；`archives/migrations.json` 是同一次事务导出的迁移历史。SQLite 的 `archive/current` 记录与修订事件保存它们，旧版本仍有内容寻址副本。重放时忽略 archive 缓存本身，避免缓存产生新迁移。

若评测/生成事实已提交、档案更新前进程结束，`archive_snapshot()` 仍能重建正确视图，`recover_experiment --apply` 或恢复已完成生成会补齐缓存。导出之前中断则沿用 P4 的待导出机制。相同事实重复重建/同步不会新增记录修订；纯检查不会写迁移。

## 需要继续研究的优缺点

优势是把“质量”和“布局类型覆盖”分开，低分但不同类型的候选有繁殖机会；岛屿延迟高分程序统一所有搜索分支。谱系、选择与迁移都可追溯，保存响应后可以离线重放。

代价和风险包括：两个特征未必反映算法多样性，微小数值变化可能跨越格子边界；新格很差的程序仍能以相同概率繁殖；四岛共用种子初期相似，最高分迁移也可能增加同质化；只用最近一次成绩对随机求解器较敏感。当前按事件全量重建、保存完整选择快照的方式利于审计，但事件多后会增加 CPU、内存和磁盘开销，尚未为大型运行做增量索引/压缩。

离线演示验证机制，不证明搜索质量提高。历史参考与预算控制已在P6/P7接入；正式实验应比较等调用/等token条件下的策略、覆盖、失败率和成本。当前真实Docker隔离验收仍待运行时，不把离线测试视为隔离成功。

## 代码阅读顺序

1. `Evolve/archive.py`：`feature_cell` 看分格；`_compete` 看同格竞争；`rebuild_archive` 看事件重放；`ring_transfers` 看同时迁移。
2. `Evolve/selection.py`：`sample_parent` 看轮询选岛和均匀抽格。
3. `Evolve/session.py`：`select_parent`、`best`、`sync_archive` 看框架接入和全局最佳分离。
4. `Evolve/generation.py`：看请求前的选择快照与恢复时复用原计划。
5. `tests/test_archive.py` 与 `tests/test_archive_session.py`：看多样性、复测、迁移与中断边界的具体反例。
